# Integration and regression audit: spatial-app

**Date:** 11 November 2026  
**Reviewed commit:** `44f2347cffca1e761350bb948df8fa7ce4f22f9f` (`main` at the start)  
**Scope:** `app.py`, `ntl/`, `tests/`, `.github/workflows/`, dependency declarations and feature-integration boundaries. **The 19,987 GeoJSONs were not revalidated.**  
**Method:** source-code review, identification of inter-module data contracts, comparison with actual CI runs, and adding synthetic regression tests. No algorithm changes were made in this PR.

> **Evidence level:** All 23 Python files in the repository were read from GitHub, and the workflow and actual GitHub Actions logs on `main` were checked. This new audit **did not** fetch Earth Engine data or run Streamlit Cloud end to end. Distinguish these limitations from regression tests on synthetic data.

### 2.1. A02: zero differs from lack of observation

- `app.py:1406–1443` computes median of valid monthly images and then applies `unmask(0.0)`.
- `app.py:1911–1927` converts zonal NaN and unjoined results to `0.0`.
- `ntl/zonal.py` preserves masked/NaN on valid rasters before extraction but defaults to `fill_missing=0.0` unless caller overrides it.
- `ntl/data_quality.py` contains appropriate metadata and warnings; `quality_ui.py` provides on-demand valid-month counts.
- **No Yanqing 2014/2020 evidence shows a missing-data defect there:** the pilot rasters had 12 valid monthly composites throughout the tested bounding rectangle. Do not treat another hypothetical scenario as a defect already affecting Yanqing.

### 2.2. A07: do not conflate two MAUP approaches

`robustness.aggregate_blocks` groups fine-grid indices by factor×factor and area-averages cell values before rerunning LISA. This is a block-aggregation experiment and **does not necessarily reproduce** raster→polygon extraction on a newly generated coarser 1,000 m grid from the boundary. Describe the distinction in interpretation and methods; do not assume errors or overwrite historical results.

## 3. New integration tests

`tests/test_pipeline_integration.py` uses an in-memory synthetic GeoTIFF and UTM 500 m polygons, with four checks:

1. **Raster → zonal mean → Local Moran → CSV:** order and identity of 16 cells, NTL values, cluster labels and CSV export/readback.
2. **Missing vs measured zero:** a measured-zero pixel, NoData sentinel and valid negative radiance remain distinguishable before `fill_missing=0`; explicitly record that final fill policy may make outputs equal.
3. **Space-Time label compatibility:** the display function must not alter raw `regime_summary` or CSV codes.
4. **Space-Time CSV contract:** numeric fields, regime codes and stability through CSV read/write.

These test modules together with synthetic data; **they do not** replace empirical Earth Engine imagery, GHSL or Streamlit Cloud. A branch/PR CI result must be treated as separate evidence, not inferred from `main`.

## 4. What has not been verified

- No Cross-location V11 evidence was gathered for the three localities in this audit; status remained **PENDING**.
- No live VIIRS/GHSL export or download, or Streamlit Community Cloud E2E completion, occurred in this task.
- Not all interactive Streamlit behaviors were checked (concurrent sessions, reload, cache reset, errors).
- No exhaustive sentence-by-sentence correspondence of English/Vietnamese README, technical specifications and UI was verified.
- No production dependency pins or changes to analysis formulas.

## 5. Acceptance and priority order

- **Immediately:** CI should run all six existing files plus the new integration file; all new tests must pass and unintended skips must not conceal failures.
- **Then:** construct an intentionally problematic dataset with NoData, low coverage and negative pixels to measure effects on LISA and CSV; change policy only after empirical results.
- **Next:** compare block MAUP coarsening with exact raster-on-coarse-grid extraction and independently check GHSL.
- **Finally:** benchmark resources and multiple sessions on Streamlit Cloud; establish a lockfile/compatibility matrix; refactor incrementally with regression coverage.

**Change rule:** do not combine algorithm repairs, CSV output changes or missing-data policy changes into a tests-only PR. Each scientific change needs its own regression tests and comparison evidence.
